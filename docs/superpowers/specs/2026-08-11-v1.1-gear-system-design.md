# v1.1 Gear System Overhaul — Design Spec

- **Date:** 2026-08-11
- **Status:** Design (brainstormed with rizdevs) — pending review
- **Bot:** Kyriz (discord.js v14, CommonJS, `data/economy.json` flat-file)
- **Related:** battle mode spec (`2026-08-08-battle-mode-design.md`)

## 1. Vision

Expand the gear system beyond Epic: introduce **Legendary, Mythic, Divine** tiers with **random stat ranges + random passive skills** (gacha). Add **floor-zone drop rates** (hard breakpoints), **crit system** (Precision passive + enemy crit at floor 45+), and **unique item IDs** for Legend+ gear. Epic ke bawah tetap sistem lama (fixed stats, shared template IDs).

## 2. Floor-Zone Drop Rates

Replace the current continuous weight function with hard zone breakpoints:

| Zone | Common | Uncommon | Rare | Epic | Legendary | Divine |
|---|---|---|---|---|---|---|
| 1-30 | 65% | 20% | 12% | 2.5% | 0.5% | 0% |
| 31-60 | 45% | 0% | 35% | 15% | 4% | 1% |
| 61-90 | 30% | 0% | 40% | 20% | 7% | 3% |
| 91+ | 0% | 15% | 40% | 25% | 12% | 8% |

**Drop values**: static per item (d1=3 ... d7=400). Drop tier distribution shifts per zone = higher zones = more 🧪/run. No change to individual drop values.

**Economy safety**: 🧪 is one-way (closed loop). Higher drop rates → more 🧪 → gear purchase (5k-20k) + reroll (65% burn per cycle) = sufficient sink. Self-balancing.

## 6. Crit System

### Player Crit
- **Source**: Precision passive ONLY (no base crit stat di v1.1).
- **Crit chance**: Precision value (5-8% Legend, 9-13% Mythic, 14-20% Divine).
- **Multiple items stack**: cap **50%** (multiple Divine w/ Precision bisa stack, tp capped).
- **Crit damage**: **1.75×** (middle ground — exciting tp gak swingy).

### Enemy Crit (PvE)
- **Floor 45+**: flat **20%** crit chance. Below 45: **0%** (safe zone).
- **Crit damage**: 1.75× (same as player).
- Implementation: `generateEnemy(floor)` adds `critChance: floor >= 45 ? 0.20 : 0`.

### Combat Application (resolveFight)
```
// In _dmg function:
function _dmg(attacker, defender, skill, critChance) {
  let dmg = skill.type === 'magic' ? magicDamage(...) : physicalDamage(...);
  if (critChance > 0 && Math.random() < critChance) dmg = Math.floor(dmg * 1.75);
  return dmg;
}
// Player attack: _dmg(playerStats, enemy, rot[pi], playerCritChance)
// Enemy attack: _dmg(enemy, playerStats, enemy.rot[ei], enemy.critChance)
```

### Interactions
- **Lifesteal + Crit**: heal = lifesteal% × (crit damage). Big crit = big heal. Good synergy.
- **Fortify + enemy crit**: Fortify reduces ALL damage (including crit). Crit dmg = base × 1.75 × (1 - fortify%). Partially mitigates crits.
- **Evasion + enemy crit**: Evasion can dodge the crit entirely (if dodge roll succeeds, no damage at all).

## 7. Unique Item System (Legend+ only)

### ID Format
`ky` + 4 random lowercase alphanumeric (e.g., `ky4f2a`). Collision-checked against user's existing uniqueItems.

### Data Structure (per-user di economy.json battle field)
```json
"battle": {
  "uniqueItems": {
    "ky4f2a": {
      "base": "weapon_atk",
      "name": "Dragon Slayer",
      "rarity": "legendary",
      "slot": "weapon",
      "stats": { "atk": 25 },
      "passives": [{ "id": "berserker", "emoji": "🗡️", "value": 11 }],
      "boughtAt": "2026-08-11T10:30:00Z"
    }
  },
  "equipment": { "weapon": "ky4f2a", "head": "g16", "armor": null, ... }
}
```

### Rules
- **Epic ke bawah** (`g1`-`g20`): shared template, fixed stats, NO unique instance. Multiple players can have `g10`.
- **Legend+** (`kyXXXX`): unique per instance. Random stats + random passives.
- `equipment` references either `g10` (template) or `kyXXXX` (unique).
- `computeStats`: `if (id.startsWith('g')) → GEAR[id]` | `if (id.startsWith('ky')) → uniqueItems[id]`.
- **Zero migration** — existing Epic gear works as-is. Only new Legend+ purchases use unique system.

### Buy Flow (Gacha Reveal)
1. Player: `ky buygear legend weapon` (or `ky buygear legend` → pick slot).
2. System: deduct 🧪 price (5,000). Generate unique ID. Roll stats (range). Roll passive(s). Store in uniqueItems.
3. Bot: reveal message — "🎉 **Dragon Slayer** `ky4f2a` — 🟠[L] +25 ATK | 🗡️ Berserker 11%"
4. Player: `ky equip ky4f2a`.

## 10. Passive Application in Combat

Passives read from equipped uniqueItems (Legend+ only). Applied per-round di resolveFight:

| Passive | Application point | Formula |
|---|---|---|
| Berserker | Damage output | `dmg *= 1 + value/100` |
| Precision | Crit chance | `critChance += value/100` |
| Lifesteal | After dealing dmg | `hp = min(maxHp, hp + dmg × value/100)` |
| Swift | Turn order only | `effectiveSpd = baseSpd + value` |
| Fortify | Damage taken | `dmgTaken *= 1 - value/100` |
| Evasion | Before taking dmg | `if (random < value/100) skip enemy attack` |
| Greed | Drop value | `drop.value *= 1 + value/100` (in rollDrop) |
| Wisdom | Char EXP | `charExp *= 1 + value/100` (in nextFloor) |

Multiple passives stack additively (e.g., 2 Berserker items: 11% + 8% = 19%). Divine with 2 passives = 2 separate passive types.

## 12. Skill System (PvE auto + PvP interactive)

Each class has 2 basic skills + 1 ultimate. In PvE: auto-rotation cycles all (w/ CD). In PvP: player picks each round.

### Warrior Skills
| # | Skill | Damage | Effect | CD |
|---|---|---|---|---|
| 1 | Slash | 1.0× ATK | Basic. No effect. | — |
| 2 | Parry Strike | 1.6× ATK + **Parry** (visible 🛡️) | Blocks ALL damage from next enemy attack (incl. ult). Debuffs (burn) tetap kena. Enemy gak dpt lifesteal on parried hit. | CD 2 |
| 3 | War Cry (Ult) | 2.5× ATK | Self-buff: +25% ATK for 2 turns. | CD 4 |

### Mage Skills
| # | Skill | Damage | Effect | CD |
|---|---|---|---|---|
| 1 | Bolt | 1.0× MATK | Basic. No effect. | — |
| 2 | Fireball | 1.7× MATK + **Burn** | Burn: 10% MATK/turn for 3 turns (refresh on re-cast). Burn goes through parry (debuff, bukan damage). | CD 2 |
| 3 | Meteor (Ult) | 2.5× MATK | **Heavy Burn**: 20% MATK/turn for 3 turns (overwrites Fireball burn). Pierce 50% MDEF. | CD 4 |

### Burn Mechanics (PvE + PvP)
- Fireball burn: 10% of caster's MATK per turn, 3 turns. Refresh on re-cast (not stack).
- Meteor burn: 20% of caster's MATK per turn, 3 turns. Overwrites Fireball burn.
- Burn ticks at start of victim's turn (before they act).
- Burn is a debuff — goes through Warrior parry (parry blocks damage, not debuffs).
- **Both PvE and PvP** (consistent).

### Parry Mechanics (PvE + PvP)
- Triggered when Warrior uses Parry Strike. Sets `parryActive = true`.
- **Visible** to opponent (shown in round display: "🛡️ Parry active!").
- Next incoming attack's **damage** = 0 (including ult). Parry consumed.
- Debuffs (burn) still apply.
- Lifesteal: enemy heals 0 (0 damage dealt on parried hit).
- CD 2 turns: Parry, [Slash/War Cry], Parry, [Slash/War Cry]... = ~50% uptime.
- In PvE: auto-rotation alternates Parry Strike / Slash.

### Skill Rotation in PvE (auto-resolve)
Warrior: Slash → Parry Strike → Slash → Parry Strike → War Cry (when off CD) → repeat.
Mage: Bolt → Fireball → Bolt → Fireball → Meteor (when off CD) → repeat.
Warrior parries every other round (~50% dmg reduction) + Mage burn DoT maintained.

## 13. PvP System (Async Interactive Duels)

### Command
- `ky battle @user` → **challenge** that user to a duel. Prefix only. (The `@user` arg distinguishes PvP challenge from a no-arg `ky battle` PvE start.)
- `ky battle` (no arg) → **PvE** delve (unchanged from v1).

### Mutual Exclusion (`canStartBattle`)
- A player in an active PvP fight **cannot** start a PvE run, and vice versa.
- `ky battle @user` is rejected if EITHER player has an active PvE run OR an active PvP fight.
- `ky battle` (PvE) is rejected if the player is in an active PvP fight.
- Enforced by a single helper that checks both `activeRuns` (PvE) and `activePvpFights` (PvP) Maps for the userId.

### Challenge Flow
1. Player A: `ky battle @userB` → challenge embed (Accept/Decline buttons) on a **single shared message**.
2. Player B: clicks Accept.
3. Both get **fresh HP = 70% of max** (computed from current level + gear + passives). Reduces fight length to 4-10 rounds. High-level-gap safety: because HP% is relative and damage scales with attacker stats vs defender DEF/MDEF, a lvl-95 with new gear vs a lvl-100 is a real fight, not a one-shot — the 70% floor keeps it to 4-10 rounds.
4. Fight state stored in `activePvpFights` Map (keyed by fightId). The shared message lives on for the whole fight.

### Single Shared Message (1 embed, both players)
- ONE message, ONE embed for the whole fight. Both players watch the same panel.
- **Name line**: `[👑 Mythic] GodSlayer Kyrion 🔥 · Lv.42 Warrior`
  - `[👑 Mythic]` = **ultra-title/logo if owned** (emoji + name in brackets). Many players own no ultra-title → omitted entirely.
  - `GodSlayer` = purchased **title** (word), if owned — omitted if none.
  - `Kyrion` = **charName** (fallback Discord username if no charName set).
  - `🔥` = purchased **badge** emoji, if owned — omitted if none.
  - Then `· Lv.X Class`. Same cosmetics rendering as `ky lb` (resolve via shopItems).
- **Gear line** (compact, one line, 5 slots): `⚔️🟠[L] Warsplitter+12 · 🛡️🟣[E] Aegisplate · 🪖🔵[R] Visor · 👢🔵[R] Swiftstep · 💍🟠[L] Berserker`
  - Format per item: `<slot-emoji><tier-emoji>[<letter>] <name>`. Tier emoji carries the color (Discord can't color text): ⚪Common 🟢Uncommon 🔵Rare 🟣Epic 🟠Legend 🟡Mythic 🔶Divine. Letter: C/U/R/E/L/M/D.
- **HP = BARS ONLY, no numbers.** `██████████████░░░░░░` (20 segments, each 5%). **Both players fill left→right** (same direction — readable). Nominal HP hidden.
- Turn indicator line: `🔄 Kyrion's turn` (arrow/emoji points at active player).

### Buttons (turn-based)
- **Only the ACTIVE player's skill buttons are shown/enabled** each turn. Inactive player sees the active player's skill row + `⏳ <ActiveName>'s turn...`. Clicking a button when it's not your turn → ephemeral **"Not your turn yet."**
- Active player's skill buttons carry their userId (`pvp_skill_<skillId>_<fightId>_<userId>`); `handleButton` rejects non-owner. Cooldowns shown `(CDn)`, disabled if on CD.

### Turn Order
- **Higher SPD goes first** (SPD = first-hit, same principle as PvE — no double-turns). Then **strict alternation A-B-A-B** for the rest of the fight.
- Swift passive (flat SPD) affects the **initial first-turn only**. Order is **fixed at fight start** — no per-turn re-roll (predictable + simple).

### AFK Timer (active player only)
- **1-minute timer on the ACTIVE player's turn.** If the active player doesn't act within 1 min → they **LOSE (forfeit)**, opponent wins. Display shows the AFK player as the loser (same screen as a `ky end` forfeit).
- Only the active player can be AFK-timed — the inactive player has no obligation, no timer.
- Timer **resets when the active player acts** (pick → turn passes → NEW 1-min timer for the new active player).
- Timer **cleared on fight end in ALL exit paths** via a single `endFight()` cleanup. This is the exact bug class that bit PvE (stale timer/collector from a previous game) — no timer survives the fight.

### Turn Flow (turn-based — NO hidden pick, NO reveal phase)
1. Turn starts for the active player. **Burn DoT ticks first** if the active player is burning (start-of-turn tick).
2. Active player sees their skill buttons (on-CD ones disabled). Picks a skill.
3. **Resolve immediately** (open pick, no simultaneous phase):
   a. Compute damage: `skillMult × ATK/MATK + Berserker buff`, then **crit** check (Precision, ×1.75).
   b. **Parry check**: defender `parryActive` → 0 damage, consume parry, popup "⚔️ Parried!" (Burn still ticks — it's a debuff, not blocked.)
   c. **Evasion check**: defender evade roll → 0 damage, popup "💨 Missed!".
   d. Apply **Fortify** (−% dmg taken) to residual damage.
   e. Apply **Lifesteal** heal to attacker.
   f. Apply **burn** from Fireball/Meteor (set/renew burn DoT on defender).
4. **2-frame animation (~1.4s)**: frame 1 = skill name + event popup (💥 CRIT / ⚔️ Parried / 💨 Missed / 🔥 Burn) + HP bar drops; frame 2 = settled HP bar + "X's turn" or fight result.
5. **Death check**: defender HP = 0 → fight end (attacker wins).
6. Alive → swap active player, increment turn count, start new 1-min AFK timer.
7. **Turn cap: 30 total turns (≈15 each).** Timeout → highest HP% wins.

### `ky end` (dual-purpose: PvE + PvP)
- In a PvE run → **extract** (bank drops + exp, as v1).
- In a PvP fight → **forfeit** (works ANY time — your turn or not). You lose, opponent wins. Same screen as an AFK loss.
- If in neither → error message.
- Clears fight + AFK timer via `endFight()`.

### Fight End
- One player dies → other wins. Or **turn cap 30** → highest HP% wins. Or **AFK / `ky end` forfeit** → non-forfeiting player wins.
- **No 🧪/exp/drops lost or gained.** Pure duel.
- W/L recorded: `battle.pvpWins`, `battle.pvpLosses`. Shown as a line on `ky char` (`PvP: XW / YL`).
- **No ELO / no PvP leaderboard** (dropped per owner call — a rating with no leaderboard adds complexity for nothing). Pure W/L record only.
- `endFight()` clears the AFK timer + deletes the fight from `activePvpFights`. The ONLY cleanup path.

### In PvP, ALL passives active
- Berserker (+% dmg), Precision (crit), Lifesteal, Swift (+SPD first-turn), Fortify (−% dmg taken), Evasion (% dodge), Greed (no effect — no drops in PvP), Wisdom (no effect — no EXP in PvP).
- Greed/Wisdom = dead passives in PvP (by design — they're PvE-only utility).

### PvP state (in-memory Map)

## 15. Balance Notes

- **🧪 economy**: closed loop (one-way). Higher drop rates → more 🧪 → gear (5k-20k) + reroll (35% sellback = 65% burn) = sufficient sink. Self-balancing.
- **Player crit cap 50%**: prevents perma-crit. Precision Divine 20% × 3 items = 60% → capped 50%.
- **Enemy crit 20%**: adds ~15% avg damage taken at floor 45+. Offset by player Precision (+7.5% DPS at 10% crit). Creates incentive for Precision passive.
- **SPD balance**: boots main source (+8-34 Divine). Accessory lower (+2-12 Divine, lower chance). Passive Swift adds flat (+3-16 Divine). Max theoretical SPD at Lv10: base 34 + boots 34 + accessory 12 + Swift 16 = 96. Enemy SPD at floor 50: ~62. Player always first. Balanced (player SHOULD be first at high investment).
- **Warrior parry in PvE**: auto-rotation alternates Slash (parry) / Heavy. Parry active every other round = ~50% damage reduction from blocked rounds. Net: ~25% less damage taken overall. Strong but not OP (balanced by lower per-hit damage vs Heavy).
- **Mage burn**: Fireball 10% MATK/turn = ~5% of enemy HP/turn (at equal level). 3 turns = ~15% HP. Significant DoT. Meteor 20% = ~10% HP/turn = devastating. Balanced by long CD (4 turns).
- **PvP fight length**: 4-10 rounds (HP 70% + skills w/ CD), turn-based strict alternation. Turn cap 30 (≈15 each, highest HP% wins on timeout). CD 4 = ult ~1-2 uses per fight. CD 2 = skill 2 every other of your turns.
- **PvP record**: W/L only (`pvpWins`/`pvpLosses`), shown on `ky char`. No ELO / no leaderboard (dropped — nothing to farm, so no anti-farm needed beyond AFK=lose).
- **PvP AFK**: 1-min timer on the ACTIVE player's turn only → AFK = lose (forfeit), opponent wins. Inactive player has no timer. Cleared via `endFight()` on every exit (anti-stale).
- **PvP animation**: 2-frame HP bar drop (~1.4s) on each turn's resolve (no reveal/pick phase — turn-based, open pick). Short + clear.
